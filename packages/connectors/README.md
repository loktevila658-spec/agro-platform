# Connector framework core (WP49-021)

Provider-neutral internal library plus registered Local Server Nest module. No provider is installed and no network/HTTP endpoint is exposed. Trusted composition registers an adapter, owner command and current server authorization policy; without all applicable registrations execution fails closed. Configuration, staging, replay and execution require LOCAL_PRIMARY. Actors are trusted authenticated server identities, never request-body identities; the policy must recheck current service/user scopes, including background execution. A future public facade must authenticate and declare its OpenAPI/permissions contract in its own WP.

Profiles are tenant scoped, immutable and version pinned. Every retry uses the original profile version, envelope, actor, correlation/idempotency key, observation time and provenance. Explicit field-path/dictionary mappings have no inferred units, defaults, fuzzy IDs, JavaScript evaluation or provider policy. Complex provider transforms belong to a separately approved adapter/profile contract. Credentials and transport-specific auth remain outside this core; references and redacted/allowlisted payloads/results only, subject to deployment SecurityProfile. Adapters receive no database handle. Raw provider bodies and secrets must not be placed in envelope/result metadata.

Inbound records first commit to durable staging. Schema validation, required-field mapping and trusted owner current permission/state/version validation precede canonical execution. Owner application commands receive the framework transaction and must atomically write their own canonical effect, audit and outbox; they must not start/commit another transaction. Canonical effects, connector receipt/status, external-ID revision and connector audit/lifecycle journal commit together. Exceptions roll them all back. Framework SQL only writes integrations-owned tables. Existing platform outbox/inbox are unchanged; a staged unique job is this framework's durable inbox/outbox receipt. `integrations.outbox` is an immutable internal lifecycle journal, not a new published domain event catalog or broker route.

Outbound execution records SENDING/attempt durably before I/O. A session advisory lock excludes simultaneous workers; connection loss releases the lock. Crash recovery, lost response and SENT transport acceptance always call the adapter's reconciliation port before any resend. UNKNOWN never authorizes resend; NOT_FOUND must be conclusive according to the provider's declared idempotency/reconciliation semantics. The same idempotency key is supplied on every submit. Exactly-once external effects depend on the adapter/provider honoring that contract; this framework does not claim to make a non-idempotent unknown external write safe. Adapter I/O is time bounded and receives AbortSignal; cancellation does not imply external rollback. Transport SENT is separate from business ACCEPTED.

Retry policy requires explicit maxAttempts, baseDelayMs, maxDelayMs, jitter and timeoutMs. Network/timeouts/temporary failures and rate limits retry with bounded exponential jitter, respecting Retry-After. No provider-specific retry values are invented. Auth/validation/mapping/owner errors require action; unknown schema and exhaustion go to DEAD_LETTER. Failed jobs retain their original intent and immutable attempt/audit history. Authorized replay requires a reason, preserves the envelope, increments lifetime attempts and starts a fresh bounded retry cycle; unknown outcomes still reconcile. Corrected data/mappings are new envelopes/profile versions with explicit supersession provenance, rather than silent edits to old DLQ intent.

External identities are unique by tenant/profile/entity type and external ID, with a unique local binding. Conflicting external-to-local or local-to-external binding fails, rolling back inbound effects. Repeated observations append provenance revisions with original observation time/profile version/job linkage. Remapping is not silently supported; a future approved correction workflow is required. No history deletion or cleanup is scheduled; deployment retention must meet the governing SecurityProfile before any future archival/purge feature.

Migration 0008 expands schema v7 to v8, preserving old data/contracts. Existing migration runner checksums and repeat checks apply; no destructive down migration. Library uses Node built-ins only; the workspace records an empty importer. API compiler consumes src/**/*.ts, and Docker copies this CJS runtime. API tests and package tests are discovered by existing CI wildcards. The deterministic fixture-only owner/provider exercises rollback, duplicates, out-of-order versions, timeout/reconcile, 429/503, DLQ and replay. It creates no production business workflow. WP49-022/023/024, provider credentials, extension SDK, status UI and generic file import are outside this package.
